# 実装への引き継ぎ（実装フェーズで扱うレビューの懸念）

本書は設計書でも実装計画でもない。`01_requirements.md`・`02_architecture.md` のレビューで挙がった、実装フェーズに属する懸念を集めたものである。実装計画（`03_implementation_plan.md`）は、各項目について、採用する方法、または当てはまらない理由を記す。本書には承認の状態がない。本書の内容と 01・02 が食い違う場合は、01・02 に従う。

## I-01: レベル・フィールドの値の流入をみるガードの網羅性

- 懸念: `02_architecture.md` 3.7 節の「レベル・フィールドの値の流入」のガードは、`Level`・`Field` の値が役割を宣言する構築関数の引数の式の中に `parts()` の受け手以外の形で現れないことを確かめる。しかし、`lvlStr := level.String()` のように一時変数へ描画してから、その文字列変数を `errmsg.Text()` などに渡す書き方を取りこぼしうる。
- なぜ重要か: この取りこぼしがあると、レベル・フィールドの値が構造を持たない `Text` に平らにされ、AC-21 が防ごうとしている役割の喪失が、ガードに検出されないまま入りうる。
- 案: 対象のパッケージで `Level`・`Field` の値に対する `.String()` の呼び出しを検出し、明示的に許可した位置（ログ・警告など）以外を拒否する静的検査を加える。0178 のガードの仕組み（型検査した本番のパッケージの集合）の上に置く。
- 関連: F-006・AC-20・AC-21

## I-02: レベル・フィールドの型のガードが認識する名前

- 懸念: `02_architecture.md` 3.7 節の「レベル・フィールドの型」のガードは、名前が `Level`・`Field` の欄と、名前が `Level` で終わる欄を対象にする。`SourceField string` のように `Field` で終わる名前の欄は、`Field` 型であるべきなのに `string` のままでもガードを通過する。
- なぜ重要か: AC-04 が求める「レベル・フィールドを描画済みの文字列で持つ欄を残さない」が、普通に書かれうる `...Field` という名前の欄で破られ、その欄が役割の構造を失いうる。
- 案: ガードが対象にする名前に、`Field` で終わる名前も含める（`Level` の接尾辞規則と揃える）。認識する名前の集合は一箇所で定義し、テストで固定する。
- 関連: F-001・F-006・AC-04・AC-20・AC-21
